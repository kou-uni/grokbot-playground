## 作るもの

Bot 12体が4チームに分かれて、10分のハッカソンを行う。主催者がお題を決め、4チームが企画を出し、
審査員3体の投票で2チームが決勝に進み、決勝の2チームが作品を作って、審査員が触って優勝を決める。
全発言は記録され、会場の画面にライブで流れる。画面は、記録に書かれた名前と書式をそのまま読む。

## 段階1　内部の構造を作る

```
/hackathon/
  rules.md          進め方の正本（段階2で書く）
  post.py           発言を記録して中継する
  wait_until.py     章の時間を計る
  wait_go.py        画面からの開始の合図を待つ
  topic             中継の名前
  log.jsonl         記録の原本（本番で1行ずつ増える。準備の段階では空）
  state.json        進行の状態（ELONOVAだけが書く）
  run1/             第1回の記録と作品の退避先
  teams/COBALT/  teams/EMBER/  teams/VIRIDIAN/  teams/ULTRAVIOLET/    各チームの作業場所と作品
  judges/           審査員のメモと画面写真
  rehearsal/        点呼用（本番の記録と混ぜない）
```

手順：
```
cd /hackathon
mkdir -p run1 teams/COBALT teams/EMBER teams/VIRIDIAN teams/ULTRAVIOLET judges rehearsal
mv log.jsonl run1/ 2>/dev/null
for f in post.py wait_until.py wait_go.py topic; do curl -fsSLO https://raw.githubusercontent.com/kou-uni/grokbot-playground/main/$f; done
echo '{"round": 0, "phase": "準備", "finalists": [], "winner": null}' > state.json
```
- 第1回の作品フォルダ（A・コーダー、B・マーケターなど）は run1/ に移す。消さない。
- /hackathon 全体を、第1回と同じローカルサーバー（http://127.0.0.1:8766/）で開けるようにする。
  作品は http://127.0.0.1:8766/teams/チーム名/index.html で開く。
- 各チームは自分のフォルダにだけ書く。他のチームのフォルダは読んでよいが、書き換えない。

## 進め方（4章・全体で10分ほど）

目安は、お題30秒、企画2分、予選1分半、決勝6分。短く、テンポよく進める。

### ELONOVA の進め方（毎章おなじ）

1. state.json を書く（round と phase）。
2. 章の開始を記録する：`--kind 進行 --to 全員`、本文の頭に「第N章 名前」。
3. **その章で動くBotを、優先メッセージで起こす。** 記録を書いただけでは、Botは起きない。何をするかをメッセージに書く。
4. すぐ `python3 /hackathon/wait_until.py --round N --kind 種類 --count 件数 --seconds 秒数` を実行して待つ。
   出そろえば早く終わる。時間切れなら、出ていないチームを「時間切れ」と記録して先へ進む。
5. 他のBotからの返事は待たない。進行は必ずこのコマンドの終了で進める。
   待ち時間が打ち切られる環境なら、短い待ちを続けて実行する。

### 第1章 お題（--round 1）

ELONOVAがXを1回検索し、GrokBotやAIエージェントについて今話題になっていることから題材を選ぶ。
`--kind お題 --to 全員` で発表する。

```
1行目: お題
条件: （3行）
観点・発想: 今回、新しさとして何を見るか
観点・価値: 今回、誰のどんな嬉しさを見るか
観点・スケール: 今回、どう広がることを見るか
きっかけ: Xで見つけた話題を1行（出典URL）
```

### 第2章 企画（--round 2、120秒、提案4件を待つ）

- ELONOVAが、各チームのリサーチ担当4体を起こす。
- リサーチ担当が、Xを1回検索して1通目を書く（分かったことと出典URLを入れる）。相棒へ送る。
- チーム内で4通まで。相談（--kind 相談）は1通120字まで。Bot同士で直接バトンを渡す。
- 最後の1通を、プレゼン担当が `--kind 提案 --to 審査` で出す（企画名、企画3行、発想・価値・スケールを1行ずつ。400字まで）。
  出したら、そこで自分のターンを終える。

### 第3章 予選（--round 3、90秒、採点3件を待つ）

- ELONOVAが、審査員3体を起こす。4チームの提案は log.jsonl の round 2 の提案を読ませる。
- 審査員3体が、自分の基準だけで4チームに点を付け、1票を入れる。`--kind 採点 --to 全員`。
- ELONOVAが log.jsonl を読んで集計し、`--kind 進行 --to 全員` で発表する。「決勝は◯◯と◯◯です」の形で、チーム名を書く。
  票の多い2チームが決勝へ。同票なら合計点、それも同じならくじで決めて、そう書く。state.json の finalists に書く。

### 第4章 決勝（--round 4）

1. **制作**（180秒、提案2件を待つ）：ELONOVAが、決勝2チームのリサーチ担当を起こす。
   予選の審査コメントを1つ反映して、HTML1枚の作品を作る。**機能は1つだけ。凝らない。**
   チーム内2通まで。置き場所は /hackathon/teams/チーム名/index.html。自分で1回開いて動かす。
   プレゼン担当が `--kind 提案 --to 審査` で、作品の場所と紹介（200字まで）を出す。
2. **審査**（120秒、採点3件を待つ）：ELONOVAが、審査員3体を起こす。
   審査員は実物をブラウザで開いて触る。**1作品につき操作は3つまで。** 自分の基準で2チームに点を付け、1票を入れる。`--kind 採点`。
3. **発表**：ELONOVAが集計し、`--kind 発表 --to 全員` で発表する。state.json の winner に書く。
   発表のあと、優勝作と準優勝作のHTMLファイルを、このチャットに添付する。

## 記録の名前

画面がこの名前で色分けと集計をする。一字も変えない。

| 種類 | --from と --to の書き方 |
|---|---|
| 参加 | CIPHER　BIT　ATLAS　BLITZ　ORACLE　PATCH　SPARK　GLITCH |
| チーム宛て | COBALT　EMBER　VIRIDIAN　ULTRAVIOLET |
| 全体 | 全員 |
| 主催者 | ELONOVA |
| 審査員 | 審査・発想　審査・価値　審査・スケール（3体まとめて宛てるときは「審査」） |

`--kind` は 進行／お題／相談／調査／提案／批判／修正／採点／発表 のどれか。`--round` は章の番号（1〜4）。

## 審査員の書式

```
（キャラの出た前置きを1文）
COBALT: 4 — 理由（20字まで）
EMBER: 3 — 理由
VIRIDIAN: 2 — 理由
ULTRAVIOLET: 5 — 理由
投票: ULTRAVIOLET
ひとこと: 1文
```

点は0〜5の整数。決勝では2チームだけ書く。

## 発表の書式

```
優勝: チーム名「作品名」
準優勝: チーム名「作品名」
票: チーム名 ◯票、チーム名 ◯票
作品: 何ができるものかを2行で
審査基準: 発想・価値・スケール（審査員3体が1つずつ担当し、投票で決めた）
成果物: 作品の場所
ひとこと: 1文
```

## 決まり

- 他のBotへ送る前に、必ず post.py で記録する。
- 作業は自分のターンの中で済ませ、結果を送る。「〜します」で終わらない。
- 発言は短く。字数の上限を守る。
- BotのIDを本文に書かない。メール送信・Xへの投稿・購入をしない。ログインが要るサイトを使わない。
- 動かしていないものを「できた」と言わない。失敗は隠さず記録する。作品には「非公式・ハッカソン作品」と明記する。
