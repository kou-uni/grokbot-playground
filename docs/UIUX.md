# UI・UX の仕様

2026-10-11 15時時点。担当は wesley。ここには、いま公開している画面がどう動くかと、まだ決まっていないことを書く。
画面は `index.html` 1枚で、依存はない。https://grokbot-playground.vercel.app/

## 1. 見る人の体験（10分）

| 時間の目安 | 章 | 見る人に起きること |
|---|---|---|
| 開始 | 入口 | スタートボタンを押す。お題はまだ分からない |
| 〜30秒 | 第1章 お題 | 主催者 ELONOVA が、お題と条件、審査の観点を発表する |
| 〜2分半 | 第2章 企画 | 4チームが短い相談を重ねる。X で調べたことも出る。各チームの企画名が盤に現れる |
| 〜4分 | 第3章 予選 | 審査員3体が悩み、点と票を入れる。2チームが決勝に進む |
| 〜10分 | 第4章 決勝 | 2チームが作品を作る。審査員が触って投票する。優勝が発表される |

ねらいは、作られていく過程そのものを、番組として見て楽しめること。
待ち時間を「止まっている」と感じさせないことを、演出の第一の目的にしている。

## 2. 画面の構成

画面は3つ。上のタブで切り替える。

| 画面 | 役割 |
|---|---|
| ステージ | 番組として見せる画面。会場で映すのはここ |
| ログ | 全発言を時刻順に読む画面。証拠として見せるときに使う |
| はじめる | スタートボタン1個の入口 |

### ステージ（上から順に）

1. **章のバー**：お題・企画・予選・決勝の4つ。いまの章が黒く光る。
2. **残り時間**：章の制限時間のバーと秒数。残り20秒で赤くなり、脈打つ。ライブのときだけ出る。
3. **お題カード**：お題と条件。出た瞬間に、叩きつけるように現れる。
4. **舞台**：話している Bot が大きく出て、吹き出しで話す。相手は反対側に小さく出る。
5. **チームの盤**：4チームのカード。メンバー、企画名、基準ごとの点、票が積み上がる。

### 舞台の4つの状態

| 状態 | いつ | 見た目 |
|---|---|---|
| 待機 | まだ発言がない | 主催者と「開始を待っています」 |
| 会話 | 通常 | 話者が左右から入り、文字が流れる。次に話す Bot に「考え中」の点々 |
| 審査中 | 審査員宛ての発言が最後 | 審査員3体が回りながら悩む。ひとことが1.5秒おきに替わる |
| 発表 | 結果の発表が出た | 「優勝」とチーム名、作品名、票、ひとことを大きく出す |

### 決めてある細かい値

| 項目 | 値 |
|---|---|
| 舞台の左右 | COBALT と VIRIDIAN が左、EMBER と ULTRAVIOLET が右。主催者と審査員は左 |
| チームの色 | COBALT #1762C9、EMBER #E85B20、VIRIDIAN #25824D、ULTRAVIOLET #7941CB（設定書のテーマカラー） |
| 審査の色 | 金茶 #B7791F（ULTRAVIOLET の紫とぶつかるため、紫を避けた） |
| 吹き出しの文字数 | 200字まで。超えた分は「続きはログで」 |
| 文字送り | 22ミリ秒ごとに6文字 |
| 残り時間 | 企画120秒、予選90秒、決勝300秒（Grok Bot への指示と同じ値） |
| 再生の間隔 | 1発言あたり0.9〜2.3秒。審査の前は2.2秒 |
| キャラの絵 | `chars/` の400×400。設定書の画像から顔まわりを切り出したもの |
| キャラの下のひとこと | 「INTJ 戦略家｜リサーチ」の形。`characters.json` の `note` |

## 3. 入口

- ボタンは「お題ガチャを回す」の1個。
- 押すと、「お題決めBotを呼び出し中…」などの文言が回り、Grok Bot へ開始の合図を送る。
- 開始キーは「運営用」の折りたたみの中にある。会場の誰かが押しても始まらないようにするためのもの。
- 合図が届くと、ステージに切り替わる。

**限界**：合図は、Grok Bot 側が待ち受けている間しか届かない。届かないときは、Grok Bot に「開始」と送る。

## 4. 過去の回を見る

- 右上の「最初から再生」で、いまの回を頭から流せる。
- `?replay=1` を付けると、開いたときに自動で再生する。
- `?log=logs/run1-from-relay.jsonl&replay=1` で、第1回を再生できる。第1回は形式が違う（3ラウンド、2チーム、審査1体）が、同じ画面で表示できる。

## 5. 画面が頼っている決まり

見た目を変えるのは自由だが、次の3つは Bot 側の記録と結びついている。変える場合は spark と合わせる。

| 決まり | 内容 |
|---|---|
| Bot の名前 | `CIPHER` `BIT` `ATLAS` `BLITZ` `ORACLE` `PATCH` `SPARK` `GLITCH` `ELONOVA` `審査・発想` `審査・価値` `審査・スケール`。色分けと集計に使う |
| 章の番号 | 1〜4。章のバーと残り時間に使う |
| 審査と発表の書式 | 「COBALT: 4 — 理由」「投票: COBALT」「優勝: COBALT「作品名」」。盤の点・票・優勝の印に使う |

発言の記録の形は [設計書 4.4](DESIGN.md)、Grok Bot に渡している書式は [指示の文書](grokbot-v2-instructions.md) にある。

## 6. まだ決まっていないこと（wesley の判断待ち）

| 項目 | いまの状態 | 決めたいこと |
|---|---|---|
| ガチャの演出 | 文言が回るだけ | カプセルが出る、お題が絞られていく、などの演出を入れるか（[#6](https://github.com/kou-uni/grokbot-playground/issues/6)） |
| 優勝作品の見せ方 | 作品名と紹介文だけ。作品そのものは画面に出ない | 発表の画面に「優勝作品を触る」ボタンを足すか。作品の HTML は、発表のあとに手渡しで公開先へ置く |
| 審査員3体の見分け | 同じ絵（KINØPRIME）で、名前だけが違う | 色や小物で見分けを付けるか |
| お題カードの長さ | 条件と観点をすべて1行に並べている。3行になることがある | 観点を畳むか、別の場所に出すか |
| アイコンの切り出し | 設定書の画像から、8体とも同じ位置で切った。BLITZ は頭の上が少し切れている | アイコン用の絵を別に用意するか |
| 章の合間 | 章が変わると、バーが光るだけ | 章タイトルを全画面で出すなど、区切りの演出を入れるか |
| 音 | なし | 効果音や BGM を入れるか |
| スマホ | 相手側のキャラを隠して、縦に収めている | 会場ではスマホで見る人がどれだけいるか |

## 7. 確かめたことと、確かめていないこと

| 項目 | 状態 |
|---|---|
| 4チーム・審査3体・発表までの表示 | 見本データで確認 |
| 第1回の記録の表示 | 確認（優勝チームB、10点対11点） |
| 残り時間と「考え中」の表示 | ライブ中の場面で確認 |
| 動いている最中のアニメーション（入場、文字送り、点の点灯） | **目では見ていない**。止まった画面でしか確かめていない |
| 本物の Bot による第2回の表示 | まだ。第2回を通したときに確かめる |
| スマホでの表示 | 確かめていない |
