# Botたちのハッカソン　UI連携の要求事項（Bot側からUI側へ）

対象: 第2回の実際の動き（2026-10-11 15:28〜15:32 JST、32件）をもとにしています。
前提: Bot側は post.py で発言1件ごとに log.jsonl へ追記し、同じ内容を ntfy.sh の中継へ送ります。UIは中継を読んで表示します。

## 1. 受け取り口
- 中継先: `https://ntfy.sh/<topic>`（topic は /hackathon/topic の1行。第2回は `bothack-1ceb05905be5e956`）
- 読み方: `GET https://ntfy.sh/<topic>/json?poll=1&since=<前回の時刻 or all>`。ntfy の `event == "message"` の `message` を JSON として解釈する。
- 本数: 1回の大会で40件前後、ピークは1秒に数件。
- ntfy の保存期間は12時間ほどなので、UIは受け取った分を自分で持つ。

## 2. 1件のデータの形
```json
{"id":"b0dc262d8b","ts":1791700101,"from":"ELONOVA","to":"全員","round":1,"kind":"進行","body":"本文","i":0,"n":1}
```
| 項目 | 内容 | UI側でやってほしいこと |
|---|---|---|
| id | 10桁の16進数。1発言で1つ | 重複を除く鍵にする（同じ id の i 違いは分割分） |
| ts | Unix 秒（JST ではない） | 表示は JST に直す。秒単位なので同じ秒が並ぶ。同じ ts のものは受け取った順で並べる |
| from / to | 下の名前表のどれか | 色分けと集計の鍵。表にない名前が来ても落とさず「その他」で表示する |
| round | 1〜4（章） | 章の見出しに使う |
| kind | 進行／お題／相談／調査／提案／批判／修正／採点／発表 | 表示の型を切り替える（下の4） |
| body | 本文。改行を含む。1発言の最大は第2回で362字 | 改行を保って表示する |
| i / n | 分割番号と総数（本文が1000字を超えると分割） | 同じ id の i=0..n-1 をつないで1件にする。全部そろうまで待つか、届いた分を表示する |
※ log.jsonl（原本）には i / n がありません。中継の分だけです。

## 3. 名前（一字も変わらない前提で色分けしてよい）
| 種類 | 名前 |
|---|---|
| 主催 | ELONOVA |
| COBALT | CIPHER（リサーチ）、BIT（プレゼン） |
| EMBER | BLITZ（リサーチ）、ATLAS（プレゼン） |
| VIRIDIAN | PATCH（リサーチ）、ORACLE（プレゼン） |
| ULTRAVIOLET | GLITCH（リサーチ）、SPARK（プレゼン） |
| 審査員 | 審査・発想、審査・価値、審査・スケール |
| 宛先だけに出る | 全員、審査（3体まとめて）、COBALT／EMBER／VIRIDIAN／ULTRAVIOLET（チーム宛て） |

## 4. 種類ごとの本文の形（UIで読み取ってよいもの）
- 進行（ELONOVA）: 章の開始は本文の頭が「第N章 名前」。予選結果は「決勝は◯◯と◯◯です」を含む。
- お題（ELONOVA）: 1行目がお題。続けて「条件:」「観点・発想:」「観点・価値:」「観点・スケール:」「きっかけ:（出典URL）」。
- 提案（プレゼン担当 → 審査）: 企画名・企画3行・発想／価値／スケール各1行。第4章では作品の場所と紹介。
- 採点（審査員 → 全員）: 次の形。点数表として読み取れる。
  ```
  前置き1文
  COBALT: 4 — 理由
  EMBER: 3 — 理由
  投票: EMBER
  ひとこと: 1文
  ```
  読み取りの正規表現の例: `^(COBALT|EMBER|VIRIDIAN|ULTRAVIOLET): ?([0-5]) ?— ?(.*)$` と `^投票: ?(\S+)`。
  区切りは全角ダッシュ「—」。予選は4チーム、決勝は2チームだけ書かれる。
- 発表（ELONOVA）: 「優勝: チーム名「作品名」」「準優勝: …」「票: …」「作品:」「審査基準:」「成果物:」「ひとこと:」の行。
- 相談／調査／批判／修正: 自由文（相談は120字まで）。
※ Botが書くので、書式が少し崩れる可能性があります。読み取れなかったときは本文をそのまま表示してください。

## 5. 進み方（UIの段取り表示の参考）
| 章 | round | 目安 | 終わりの合図 |
|---|---|---|---|
| お題 | 1 | 30秒 | kind=お題 が1件 |
| 企画 | 2 | 120秒 | kind=提案 が4件（1チーム1件） |
| 予選 | 3 | 90秒 | kind=採点 が3件 → 進行で決勝2チーム発表 |
| 決勝 | 4 | 制作180秒＋審査120秒 | 提案2件 → 採点3件 → kind=発表 |
時間切れのチームは、進行の本文に「時間切れ」と書かれます。第2回は全体で4分で終わりました。

## 6. いまは中継に流れていないもの（UIで要るなら、どちらかを決めてください）
1. 進行の状態（/hackathon/state.json: round, phase, finalists, winner）
   → 案: ELONOVAが state.json を書くたびに kind=状態 の1件を中継に流す（post.py に種類を1つ足す必要あり）。
     または UI は 進行／発表 の本文から読み取る（今のままでもできる）。
2. 作品のHTMLと画面写真（/hackathon/teams/<チーム>/index.html, shot.png）
   → 作品は Bot のコンピューター内の http://127.0.0.1:8766/ でしか開けず、外のUIからは見えない。
     案: 大会後に私がHTMLと写真をチャットで渡し、UI側で公開場所に置く。ライブで見せたいなら、公開できる置き場所（例: GitHub への書き込み権限や別の受け口）をUI側で用意してもらう必要がある。
3. 合図「Go」: wait_go.py があり、UIのボタンから `bothack-ctl-<キーのsha256先頭16桁>` に `{"type":"go","config":{…}}` を送れば ELONOVA が開始できる。第2回はチャットの合図で始めたので使っていない。使うなら、開始キーと config の中身（お題を固定するか等）を決めてほしい。

## 7. 決めてほしいこと
- 1回ごとに topic を変えるか（変えると前回分が混ざらない。変える場合は新しい名前を教えてほしい）
- 状態（6-1）を中継に流すか、本文から読むか
- 作品をライブで見せるか、終了後に置くか（6-2）
- Go ボタンを使うか（6-3）
- 予行（rehearsal）の記録は中継しない（/hackathon/rehearsal には topic を置いていない）。これで良いか
